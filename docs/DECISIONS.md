# Decisions

| Date | Decision | Reason |
|------|----------|--------|
| 2026-10-20 | Square grid, 40×24 tiles, 24px per tile | Much simpler picking, city radius, borders and A* than hex; fits 480×272 |
| 2026-10-20 | English UI first, full string-ID i18n | Allows Chinese later without rewriting UI |
| 2026-10-20 | Standard + timed modes; 30/60/90 min, default 60 | Player choice; timed mode is optional pressure |
| 2026-10-20 | Timed mode counts player-action time only | AI turns and menus should not punish the player |
| 2026-10-20 | 3 manual saves + autosave | Small, predictable save UI; autosave protects progress |
| 2026-10-20 | City management and diplomacy are the design focus; combat is light | Matches the requested priorities and PSP controls |
| 2026-10-20 | C99, GU 2D, static pools, no per-frame malloc | PSP 1000 has 32MB and no room for allocator surprises |
| 2026-10-20 | No `-lpspsdk`, no `-lm` | Avoid 8002013C and unnecessary imports on CFW |
| 2026-10-20 | Generated assets committed, regenerable with `make assets` | Build remains reproducible without Python, while art stays editable |
| 2026-10-20 | Milestone commits + `HANDOFF.md` at context limit | Keeps a new conversation from needing the full chat history |
| 2026-10-20 | GU vertex structs are `packed` with `_Static_assert` checks (`RectV` 16 bytes, `TextV` 24 bytes) | An `aligned(16)` `TextV` was silently padded to 32 bytes and made all text invisible; assertions catch ABI drift |
| 2026-10-20 | Do not explicitly link `-lpspuser`; use the PSPSDK default libraries | Explicit `-lpspuser` produced `psp-fixup-imports` stub-order warnings; the default link is clean and imports resolve in PPSSPP |
| 2026-10-20 | Vertex buffers are 64-byte aligned, written through the cached alias, and flushed with `sceKernelDcacheWritebackRange` before each draw | On PSP 1000, uncached vertex stores shared a cache line with per-frame counters; dirty cache writeback overwrote the first title vertex. PPSSPP does not emulate this cache behavior |
| 2026-10-20 | M1 terrain/resource atlas is 128×128 `GU_PSM_5551` instead of `GU_PSM_5650` | Resource icons need transparency (1-bit alpha, A bit 15); `GU_PSM_5650` has no alpha channel. Bit layout R 0–4, G 5–9, B 10–14, A 15, verified against `oslib` |
| 2026-10-20 | Map generation keeps only the largest connected landmass and forces at least one of each resource | No navy in scope, so all land must be reachable on foot; resource guarantees keep early gameplay options available on every seed |
| 2026-10-20 | Fog has three states (unexplored/explored/visible); the cursor is a temporary vision source with radius 4 | Matches classic 4X fog; no units exist in M1, and the cursor keeps exploration feedback and testing possible |
| 2026-10-20 | Render flush order is sprites → rects → text; the map flushes under a scissored viewport before the HUD | Map draws must be wrapped by the scissor state; batching by layer avoids state churn and stops the HUD from being overwritten |
| 2026-10-20 | Map logic is host-testable: `make test` compiles `src/map.c` with the host compiler | Determinism, connectivity, resource presence, and fog invariants are checked without a PSP or emulator run; PPSSPP remains the visual gate |
| 2026-10-20 | The map screen's Select button regenerates the same seed (debug only) | Gives a one-button on-device reproducibility check for the hardware smoke test; host tests remain the authoritative proof |
| 2026-10-20 | M1.1: enlarged the map from 40×24 to 64×48 and raised the land ratio from ~59% to ~72% average | Playtest feedback. 3072 tiles cost only ~15KB in the `Map` struct and rendering is viewport-culled, so the runtime cost is unchanged; climate bands and the hills threshold were rescaled for the new height, and host tests now enforce a 60–85% land band plus full terrain presence |
| 2026-10-20 | M1.2: calibrate the analog stick center at boot (8 samples), use a rescaled 28-unit deadzone, and let the D-pad suppress stick panning while held | On a real PSP 1000 the worn stick rested off-center beyond the fixed 24-unit deadzone, so the camera crawled left on entry and stick input seemed ignored (PPSSPP with a keyboard never shows it). Calibration cancels the hardware offset, the rescale removes the deadzone jump, and D-pad priority keeps the follow camera responsive even with a bad stick |
| 2026-10-20 | M2: move units with a free cursor + Cross, not by pushing the D-pad in the unit's direction | The PSP D-pad cannot comfortably express 8-way movement without simultaneous presses. A free cursor with a green reachable preview and Dijkstra movement is readable, works for any distance within the turn, and keeps the D-pad for cursor control |
| 2026-10-20 | M2 movement: straight 2, diagonal 3, +2 entering forest or hills; mountains and water impassable; one unit per tile; friendly city tiles enterable | Half-points make diagonal movement meaningfully cheaper than two straight steps without fractional stats. Terrain penalties are simple to explain. Blocking mountains/water is an M2 acceptance requirement; no stacking avoids ambiguous selection and combat later |
| 2026-10-20 | M2 units: settler 6 move / sight 2, warrior 6/2, scout 8/3 | Settlers and warriors share a baseline; the scout trades combat strength for range and sight. Small integers keep the HUD and path budget readable |
| 2026-10-20 | M2 starts with 3 settlers, 2 warriors, 1 scout, with settlers at least 3 tiles apart | M3 production does not exist yet, so the “found 3 cities” acceptance test must be reachable immediately. This is an explicit milestone-only setup, not the final game start; the spacing guarantees all three foundings are legal |
| 2026-10-20 | M2 city founding: Chebyshev minimum distance 3, land only, consumes the settler, population 1, vision 2, 10 original names | Chebyshev matches the square grid and prevents cramped cities. Consuming the settler is the classic 4X rule. Names are original and stored as string IDs for later localization |
| 2026-10-20 | M2 fog is the union of unit and city vision; explored tiles persist; the cursor is no longer a vision source | Units and cities now exist, so exploration should follow them. Persisting explored tiles is the classic three-state fog; removing cursor vision prevents free map reveal |
| 2026-10-20 | M2 unit and city sprites live in row 4 of the existing 128×128 `GU_PSM_5551` terrain atlas | Reuses the established texture path and 1-bit alpha; no second texture upload, no extra draw state. The atlas has unused rows below the terrain/resource rows |
| 2026-10-20 | M2 actions: Triangle opens Found City / Wait / Cancel for the selected unit; errors are toasts; Select ends the turn; L/R cycles units with moves | Matches the planned PSP control scheme. Wait is the standard “done with this unit” action; auto-advance keeps the turn moving. Select is the natural end-turn button and is reachable without a menu |
| 2026-10-20 | `Input_Pressed`, `Input_Repeated`, and `Input_Held` return a boolean (1/0), not the masked button bits | M2 initially read `Input_Repeated(NAV_MASK)` as a bitmask, so cursor movement was always zero. The API now documents the boolean contract; callers that need directions make one call per button |
| 2026-10-20 | M2 Dijkstra uses static scratch buffers and a hard `MAP_TILE_COUNT` heap guard | The search budget is at most 8 points, so the reachable region and duplicate heap pushes stay far below the guard. The guard makes a future larger movement budget fail safely instead of corrupting memory |
| 2026-10-20 | M2 water/mountain blocking is proven by host tests; the in-game denial demo uses a mountain | The M2 start area has no water in view, and host tests can isolate both cases deterministically. The PPSSPP run still demonstrates the mountain denial with a full move budget and a MOUNTAIN tile-info readout |
| 2026-10-20 | M3: the market building grants +4 gold (not +2) | A one-city economy with five buildings and five units went negative in PPSSPP; +4 keeps a typical 30-turn run solvent. Balance is centralized in `src/data.c` |
| 2026-10-20 | M3: city vision is a square covering the entire 5×5 work area | Unit vision stays circular, but the city screen must not show owned work tiles as black fog. Square radius-2 vision keeps all buyable/workable tiles visible and revealed on purchase/growth |
| 2026-10-20 | M3: building upkeep is 1–2 gold and unit upkeep is 1 per 3 units (rounded up); a negative treasury halves city production and science | Upkeep makes economy real; the halving prevents an infinite-debt spiral and gives breaking the treasury a measurable cost |
| 2026-10-20 | M3: the city screen uses four tabs (Overview / Production / Citizens / Buildings) and a 36px 5×5 grid | D-pad-tab navigation keeps every management action reachable without a cursor; 36px keeps yield text legible at 480×272 |
| 2026-10-20 | M3: tile purchase and border growth use 8-way adjacency and reveal the tile immediately | Matches the square work grid; diagonal expansion keeps territory contiguous with the 5×5 mask and avoids fogged tiles |
| 2026-10-20 | Map-click to open a city: Cross/Triangle on a friendly city tile opens the city screen even when a unit is selected there | Selecting the city is the more useful action and removes the need to deselect the unit first; that unit can still be selected via L/R or Triangle on an adjacent tile |
| 2026-10-20 | M4: one active research at a time; science from all cities is banked into it each turn | Simple to read on the PSP; avoids a complex per-city tech allocation UI while still making Libraries/Universities meaningful |
| 2026-10-20 | M4: tech requirements live on production definitions (`required_tech`) and on an improvement mapping, not in the UI | Keeps balance data centralized and lets host tests verify every gate; the UI only renders/denies |
| 2026-10-20 | M4: lock is visible (REQUIRES TECH/LOCKED) rather than hiding locked items | Players can plan a tech path; hiding unlock targets would make the tree opaque |
| 2026-10-20 | M4: completion stops research instead of auto-selecting the next tech | Makes the next choice deliberate and keeps the Science tab meaningful; overflow is discarded |
| 2026-10-20 | M4: 18 techs/4 eras in the first slice; worker-based improvements and the remaining 12 techs deferred to M4.1 | Delivers a complete research vertical slice (UI + gates + units) without expanding unit art/worker mechanics in the same step |
| 2026-10-21 | M4.1: Worker costs 10 production, has 4 move / 2 sight, and requires no technology | The worker is the delivery mechanism for improvements; gating the worker itself would delay the whole feature behind an unrelated tech. A cheap early unit makes the build menu discoverable |
| 2026-10-21 | M4.1: improvements require a tile owned by a friendly city, exclude the city center, and cannot overwrite an existing improvement | Keeps improvements tied to city development and avoids improving neutral/enemy land. Excluding the center prevents a farm/mine from replacing the city tile's fixed yields |
| 2026-10-21 | M4.1: Farm on grassland/plains/desert; Mine on hills or iron/gems; Pasture on horses; Quarry on stone; Road on any land | Small, readable terrain rules that make each resource meaningful without adding a full improvement-requirement editor; host tests pin every case |
| 2026-10-21 | M4.1: construction is instant and consumes all of the worker's remaining movement | Avoids a multi-turn work queue/state machine in the first worker slice while still making each worker one improvement per turn. A work timer can replace this later without changing the map data |
| 2026-10-21 | M4.1: roads reduce the movement cost of entering the road tile by 1, minimum 1 | Gives roads an immediate gameplay effect with the existing half-point movement system; no separate road-network graph is needed |
| 2026-10-21 | M4.1: Triangle prefers the unit action menu on a city tile; Cross remains the city-open button | Workers spawn on/garrison units stand on city tiles. City-first Triangle made their action menu unreachable without moving away; unit-first Triangle keeps both actions available (Cross for city, Triangle for unit) |
| 2026-10-21 | M4.1: locked improvements stay visible in the build menu with LOCKED | Consistent with M4 production/tech lists: players can see what Pottery/Mining/etc. will unlock instead of guessing |
| 2026-10-21 | M5: units have 100 HP; damage is `30 + (attack - defense) * 5`, clamped to 5..95; a surviving defender counterattacks | One deterministic, testable formula keeps the light-combat scope. The clamp prevents one-sided invulnerability while preserving strength differences; counterattacks make attacking without preparation costly |
| 2026-10-21 | M5: forest/hills add +1 defense; a city adds `City_Defense`; attacking consumes all remaining movement | Terrain and city walls matter without adding cover/fortification rules. Consuming movement prevents multi-attack kiting and makes positioning the core tactical decision |
| 2026-10-21 | M5: city capture requires a military unit adjacent to an empty enemy city center; killing the garrison and advancing into the center also captures | No siege HP, ranged attack, or razing yet. Empty-center capture keeps the rule readable and lets a winning field battle translate directly into conquest |
| 2026-10-21 | M5: capture reduces population by 1, clears the queue/production/food/influence, unlocks tiles, and transfers ownership immediately | Prevents captured cities from inheriting a full build queue or locked citizen plan; the population loss is the only occupation penalty until unrest/siege systems exist |
| 2026-10-21 | M5: attacking a major civilization at peace auto-declares war; barbarians are always at war | Removes a hidden “declare war” step before combat and matches the simplified diplomacy scope. Player-facing war/peace negotiation is deferred to M6 |
| 2026-10-21 | M5: three rival civs plus barbarians; AI processes synchronously in `World_EndTurn`; rivals cap at 4 cities, declare war after turn 12, and sue for peace when reduced to one military unit | A small, deterministic AI is enough to validate the 4X loop on PSP 1000 and keeps turn time predictable (<1s per AI civ). Synchronous turns avoid a scheduler/state machine in this slice |
| 2026-10-21 | M5: the player only pays economy/upkeep and sees owner-filtered vision; AI cities grow and produce without gold/science or research/workers | AI cheats only in the systems not implemented yet, so the player economy stays honest while rivals remain credible. AI research/workers can be added in a later balance pass |
| 2026-10-21 | M5: barbarians spawn near the player every 8 turns up to 4 raiders and always attack | Creates early pressure and a source of combat without requiring a full barbarian camp system. The cap prevents an unwinnable accumulation on 32MB hardware |
| 2026-10-21 | M5: Triangle → GARRISON moves a military unit into an adjacent empty friendly city; the unit stays selected and Cross on a friendly city still opens city management | Cross on a city is already reserved for management, so without an explicit action an existing field unit could never enter its own city. Keeping the garrison selected makes immediate defense and counterattacks practical |
| 2026-10-21 | M5: AI combat/capture diagnostics are logged; host tests link `tests/log_stub.c` | PPSSPP screenshots are unreliable through WSLg, so first-hand damage/HP/death/capture evidence comes from the log. The stub keeps the same gameplay code linkable by host tests without PSP filesystem symbols |
| 2026-10-21 | M6: relations are symmetric (-100..100) with HOSTILE/COLD/NEUTRAL/FRIENDLY/ALLIED bands | Symmetry keeps every check and UI readout simple; bands give the player readable thresholds without exposing the raw number alone |
| 2026-10-21 | M6: seven actions — war, peace, NAP, open borders, alliance, trade, gift | Covers the planned M6 acceptance set while staying within the four-face-button screen. Resource trade is deferred |
| 2026-10-21 | M6: gifts cost 10 gold, not the drafted 25; gain starts at +12, falls by 2 per gift to +4, and is halved during war | With a 20-gold opening treasury and a near-zero one-city surplus, a 25-gold gift made the entire relation ladder unreachable in normal play. Ten gold lets two gifts unlock open borders/trade and preserves diminishing returns |
| 2026-10-21 | M6: NAP and open borders last 10 turns with separate counters; alliances are permanent until war/elimination | Separate counters avoid one treaty silently extending the other; permanent alliances make the diplomatic-victory countdown meaningful |
| 2026-10-21 | M6: trade is AI-pays-player 2 gold/turn for 10 turns; rivals start with 30 treasury and earn city gold | A real AI treasury makes the payment honest and gives trade a visible economic effect without implementing resource commodities. Gold-only trade is the M6 slice |
| 2026-10-21 | M6: open borders/alliances share vision of partner units/cities, but do not gate physical border movement | There is no foreign-territory movement rule yet, so border gating would require a separate pathfinding slice. Map sharing is an immediate, testable benefit and is labelled as map sharing in the UI |
| 2026-10-21 | M6: AI declares war only below relation 20 and when no NAP/alliance blocks it; peace is evaluated through `Diplomacy_WouldAcceptPeace` | Keeps AI behavior consistent with the same rules shown to the player and prevents treaty-blocked declarations |
| 2026-10-21 | M6: AI proposes peace/NAP/alliance; AI-AI diplomacy is low-frequency, can end long wars, and cannot start a war against a player ally | Gives the world autonomous change without stealing focus; protecting player allies prevents the diplomatic-victory path from being sabotaged by a hidden AI war |
| 2026-10-21 | M6: treaties block attacks/captures with `COMBAT_ERR_TREATY`, shown as `TREATY BLOCKS WAR` | Diplomacy must have mechanical teeth; the explicit error tells the player why an attack is unavailable instead of silently failing |
| 2026-10-21 | M6: diplomatic victory requires alliances with every living rival for 10 consecutive end turns, at least two living rivals, and no AI-AI war among them | Prevents a one-rival cheese win and ensures “diplomatic” victory reflects a peaceful network rather than separate alliances with mutually hostile AIs |
| 2026-10-21 | M6: Start opens diplomacy from the map; Circle returns; Cross/D-pad drive the list and action popup | One-button access keeps diplomacy adjacent to the map without adding a menu layer; the layout matches the existing city/menu control grammar |
| 2026-10-21 | M7: save format is a versioned raw snapshot of `Map`, `World`, and `SaveView` plus a 68-byte header and FNV-1a checksum | The game is single-player and all state is already fixed-size; a raw snapshot needs no allocator, no serializer tree, and is easy to validate. The version/magic/size checks make future migration explicit |
| 2026-10-21 | M7: autosave after every completed turn; manual slots 1–3; load lists autosave and slots from pause and main menu | Bounded UI and predictable wear. One autosave protects progress without a ring buffer; manual slots let the player keep branch points |
| 2026-10-21 | M7: timed mode counts wall time only in MAP/CITY/DIPLOMACY; menus and pause are free; score victory compares against the best living rival, ties go to the player | Preserves the existing “player-action time only” decision while allowing city/diplomacy planning. The rival comparison gives a concrete winner without a full scoreboard screen |
| 2026-10-21 | M7 score: population ×6, cities ×10, territory ×1, buildings ×5, units 4 + HP/25, techs ×10, positive treasury/20 | Rewards the four core systems (growth, expansion, development, research) and keeps the numbers small enough to read on the results screen |
| 2026-10-21 | M7 science victory means all 18 currently available techs, not the planned 30 | The tech tree currently has 18 techs; making victory require nonexistent content would deadlock the science path. This is recorded as a simplification until M8 expands the tree |
| 2026-10-21 | M7 saves are plain files under `SAVEDATA` rather than a full `PARAM.SFO` savedata package | `PARAM.SFO` and the save-manager UI are not needed for in-game load; plain files avoid another binary format and make host testing simple. The system save manager may not list them |
| 2026-10-21 | Analog drift: 15-sample median center at boot/New Game, adaptive 32–56 deadzone, convergent low-pass, minimum output, and 45-frame zero-output recenter | The PSP 1000 stick is worn and rests off-center; a median rejects spikes, the adaptive deadzone covers larger bias without making small legitimate pushes impossible, and recentering stops the camera crawling when the stick is released |
| 2026-10-21 | Analog recalibration is exposed in Options and Pause | Hardware wear changes over time and per session; a player-facing recalibration avoids forcing a reboot or rebuild when the stick center drifts further |
| 2026-10-21 | M8 appends 12 techs after the original 18 enum values; save version and `World`/`Map` layouts stay unchanged | Preserves M7 save bit positions and loadability. New bits are simply unknown to older builds; the new techs have prerequisites that keep progression sensible |
| 2026-10-21 | M8 tech effects are one small data-driven effect per tech, applied in city/world yield code | Gives every tech a concrete benefit and a readable Science detail line without a large effect scripting system |
| 2026-10-21 | M8 science victory uses Astronomy + Scientific Method + Navigation as three “projects” | Makes the science path reachable in a standard-length game without a separate project UI; documented as a simplification |
| 2026-10-21 | M8 AI research is derived from the turn counter (one tech per 8 turns) rather than saved | Keeps the M7 save layout and deterministic behavior; AI units/buildings/score consume the derived mask |
| 2026-10-21 | M8 standard mode ends after turn 200 via `World_FinishScoreGame`; results clamp the displayed turn to 200 | Delivers the planned standard score ending with the existing score formula. City-screen turns use the same autosave/limit path as map turns |
| 2026-10-21 | M8 Help is four static pages reachable from main menu and Pause | Gives a tutorial without a separate scripted scenario or new save state; the PSP control grammar stays unchanged |
| 2026-10-21 | M8 Science list remains a flat 8-row scroll with a selected effect line | The 480×272 screen cannot show a readable 30-node tree and details at once; a flat list is a reliable PSP-sized presentation |
| 2026-10-21 | M9 Chinese is the default UI language, with an English toggle in Options | The requested release target is Chinese; keeping English selectable preserves existing UI validation and gives a fallback if a translation issue appears |
| 2026-10-21 | M9 packs only characters used by the string table plus digits and hard-coded UI punctuation into a 512×256 RGBA atlas; ASCII keeps 8px advance, CJK 16px | Keeps the atlas budget bounded (512KB at introduction, 1MB after the manual expansion) while supporting all strings. Variable-width metadata avoids making Latin text double-wide |
| 2026-10-21 | M9 uses Noto Sans CJK SC Medium at 14px in 16×16 cells | At 15px several descenders exceeded the cell; 14px keeps every checked CJK glyph inside the cell and remains readable at 480×272 |
| 2026-10-21 | M9 keeps a separate English atlas and switches textures at runtime instead of re-laying out English for 16px cells | Preserves the already-validated English UI and avoids a global 2px vertical shift in every screen |
| 2026-10-21 | M9 uses 17–18px Chinese line spacing and reduces dense lists (Science 6 rows, Production 4 rows, diplomacy 56px rows) | Chinese glyphs are 16px high; keeping the old 14px row pitch caused overlapping text. Adjusting the lists is safer than shrinking the font below legibility |
| 2026-10-21 | M9 language choice is session-only, not stored in the save/config | Avoids changing the save format or adding a settings file; the release defaults to Chinese and the option is one screen away |
| 2026-10-21 | M9.2 uses five per-owner sprite variants in the terrain atlas rather than runtime tinting | Team color is applied to intentional accent pieces (tent, shield, cloak, flag/banner, shirt) so skin, wood, stone, and metal colors stay natural; five 24px rows add only 32KB to the 5551 atlas |
| 2026-10-21 | Every unit/city also gets a 20×3 owner bar under the icon | The small 7×2 bar was easy to miss at 24px; the wider bar and accent pieces reinforce ownership when several civs meet |
| 2026-10-21 | The Chinese atlas includes every printable digit plus hard-coded UI punctuation such as `,`, `!`, `?`, and `>` | Coordinates and the production queue use literal punctuation outside the CSV; omitting the comma caused coordinate text like `2?24` |
| 2026-10-21 | M9.3 map connectivity treats mountains and water as barriers, not just “land vs ocean” | Mountains are land for `keep_largest_landmass` but impassable to units; mountain rings could enclose 1–35 passable tiles. Forest is passable and is not a barrier |
| 2026-10-21 | M9.3 carves the shortest mountain pass to isolated walkable pockets; if no mountain route exists, those tiles become mountains | Preserves playable land instead of deleting whole valleys, while guaranteeing no unit can be trapped. Carving happens before resource placement, so resources follow the final terrain |
| 2026-10-21 | M9.3 raises `test_map` coverage to 100 seeds and checks all passable tiles are reachable from the start | The previous “all land connected” check passed while 97/2000 seeds still had trapped walkable pockets; the regression test now matches unit movement |
| 2026-10-21 | M9.4 renders the minimap as one cached 64×64 GU_PSM_5551 texture rather than 3072 tile rectangles | The renderer batches at most 1024 rects; a texture keeps the minimap at 8KB and one quad, while retaining per-tile explored/visible detail |
| 2026-10-21 | M9.4 keeps the minimap collapsed by default at the bottom-right, with a `小地图 L+R` button and an L+R toggle | Preserves map space on the 480×272 screen while keeping the map one shoulder-chord away; no face-button slot or settings row is consumed |
| 2026-10-21 | M9.5 removes the minimap title bar, reduces it to 112×84 map content (114×86 panel), and anchors it above the bottom-right HUD | The title duplicated the visible content; the smaller panel leaves more playfield and still shows explored terrain. The collapsed `小地图 L+R` button is the discoverability cue |
| 2026-10-21 | M9.6 animates menu state changes with a 20-frame black fade, staggered right-to-left row slide, and an 8-frame gold selection glow | Gives menus a more polished feel without capturing/replaying the previous framebuffer or adding a separate animation state machine. The overlay is a single rect and the row offsets are a few pixels, so GPU cost is negligible |
| 2026-10-21 | M9.7 replaces the SRC audio path with standard `sceAudioChReserve` at 44100Hz and writes back the mix buffer before output | SRC output initialized in PPSSPP but did not play correctly on the PSP 1000. The standard channel matches common PSPSDK audio usage; explicit cache writeback is required because audio DMA reads main memory directly |
| 2026-10-21 | M9.7 expands Help from 4 to 12 pages instead of adding a separate manual state | Reuses the existing Help navigation and back-stack while giving new players a complete reference: goals, controls, turns/fog, cities, citizens, science, combat, diplomacy, victory/score, buildings, unit/terrain stats, and settings/tips |
| 2026-10-21 | M9.8 fixes audio normalization by scaling fractional samples to the 16-bit range (`peak * 32767`) and adds a WAV peak regression check | The initial generator normalized to 0.0–0.36 and then cast to int, so every PCM sample and WAV was zero. The check fails the build/test gate if generated audio is silent |
| 2026-10-21 | M9.9 normalizes generated clips to 80% full scale, keeps music at 70% gain, and ducks music to 20% during SFX | The user reported audio was too quiet after the silent-PCM fix. 80% peaks give clear SFX while leaving a little headroom; ducking prevents clipping when music and SFX overlap |
| 2026-10-21 | M9.10 raises music gain from 70% to 100%, while retaining 80%-peak sources and 20% ducking during SFX | The user still found the background music quiet. With 80%-peak assets, 100% gain gives about 80% output peak; ducking keeps music + SFX below full scale during overlap |
| 2026-10-21 | M9.11 adopts the user-edited `docs/GAME_DATA.md` balance: extra terrain/improvement gold, richer building bonuses, and food-per-population 3 | Keeps the design document as the source of truth and updates code/tests/manual together so displayed and simulated values cannot drift apart |
| 2026-10-21 | M9.12 uses compact F/P/G/S/I/D labels to show every nonzero building effect, and adds tile science to the city grid/detail | Several buildings now grant multiple bonuses; the old first-match effect formatter hid most of them. Compact labels keep the buildings list within its narrow column |
| 2026-10-21 | M9.4 synthesizes audio in Python and mixes it on a dedicated SRC thread at 22050Hz stereo | No external audio assets or decoder dependencies; the thread blocks on audio output and leaves the main 60fps loop untouched. Music can be toggled independently of SFX |
| 2026-10-21 | M9.4 uses only one active SFX voice plus the ambient loop | Gives clear UI/action feedback with a tiny mixer and predictable CPU/memory cost; overlapping SFX are intentionally out of scope |
| 2026-10-21 | M9.4 XMB art uses a gradient/compass/city-skyline composition instead of the tiled terrain field | The tiled field read as a debug map; the new artwork is closer to a release title screen while keeping the gold/dark CIVITAS palette |
| 2026-10-22 | V0.2 gives cities 100 HP and a separate 100 defense pool; damage drains defense before HP and capture requires 0 HP | Makes city assault a multi-turn investment instead of an instant empty-tile capture, while keeping one simple damage rule that AI and player share |
| 2026-10-22 | A garrison on the city center blocks city assault; killing it only clears the tile | Preserves the M5 garrison action and makes the city center tactically meaningful without adding a separate siege UI or battle state |
| 2026-10-22 | City defense never regenerates and is repaired by an adjacent worker for +25 (+15 with Walls); HP recovers +10 at end of turn only if the city was not hit | Creates distinct pressure and recovery rules: defense is a consumable escrow, HP is the long-term siege clock, and the player must commit workers to hold a threatened city |
| 2026-10-22 | Walls raise the defense cap to 150 and reduce repair to +15; building Walls does not free-heal current defense | Walls are a durable defensive investment with a tradeoff, not an instant full repair. The cap and repair values are simple constants that fit the existing building data |
| 2026-10-22 | City HP recovery runs after all player and AI attacks at `World_EndTurn`, not in city production processing | Prevents a besieged city from healing before the AI attacks. Ordering all attacks before one recovery pass keeps the “not attacked this turn” rule deterministic |
